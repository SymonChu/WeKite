# 群聊归拢

> 把群聊按分组收进主页若干条目，点条目就地展开 / 收起

## 类别

聊天

## 类型

可开关 & 可点击

## 描述

微信主页的会话列表里，群聊本来和好友混在一起，新消息一多就把好友会话顶下去。开启本功能后：

- 主页列表里每个**分组**占一条入口条目（置顶显示），条目上写「分组名」+ `N 个群聊 · M 条未读` + 未读角标；
- 没有归入任何分组的群自动进「其他群」兜底条目，所以主页只剩好友会话 + 几个分组条目；
- **点条目 = 就地展开**：该分组的群立刻回到主页列表，副标题变成「… 已展开，点此收起」；再点一次收回。
  不跳转、不弹窗，只有列表数据变化；
- **长按任意群** → 菜单「移入分组」：选已有分组、新建分组，或移出回到「其他群」；
- **长按分组条目** → 菜单「重命名分组」；
- 群消息、未读、置顶等行为不受影响；
- **关掉开关即完整还原**：入口条目消失，群回到原位（含原来的置顶状态）。

## 实现要点

- 每条入口条目是 `rconversation` 里一条 `username = wekite_groupagg_<分组 id>` 的真实会话行（配一条 `rcontact` 昵称），
  既作为主页条目的数据源，也是分组成员 `parentRef` 的归属目标。
- 收起时成员群 `parentRef = wekite_groupagg_<id>`（微信自己的「不显示该聊天」机制，不删数据）；
  展开时清空该字段，群回到根级列表。
- 入口行由模块自绘（`getView` 钩子里按 username 换掉返回值）：圆形首字图标 + 名称 + 计数 + 未读角标，深色模式跟随主题。
- 锚点只锚日志串，不写死混淆类名：列表 bind（`Get Item duplicated: positionMaps…`）、点击
  （`MicroMsg.ConversationClickListener`）、长按菜单（`MicroMsg.ConversationLongClickListener`）、
  宿主写 `parentRef` 的两条 SQL 通道。
- 异常自愈（`群聊归拢守护`，常驻）：微信启动时若发现「开关已关但改动还在」或「入口行被微信清掉」，
  自动还原群聊显示，避免「群被藏了又没有入口」的死局。
- 宿主进程里**不使用 Compose**：入口行自绘与系统 `AlertDialog` 之外没有自建 UI。历史上两版闪退都源于
  在宿主进程里跑 Compose 弹窗 / 复用宿主会话盒子页，已分别移除。
